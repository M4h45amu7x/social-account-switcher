# Local account profile capture (t-593)

No new network call, permission or dependency is used. Add/Update reads the exact tab captured when the popup opened, matches identity, sanitizes, then saves optional metadata beside the existing unencrypted account label. This makes list rendering independent of the encrypted session vault. Lock still shows the lock screen; it is not encryption for account metadata. When the captured tab is on another site, open the desired platform and reopen the popup before Add; the extension does not borrow a different tab or window. Legacy labels are custom. Rename (even to the same text) permanently makes a label custom. Update replaces profile fields, clears unavailable fields and refreshes automatic names; it never changes custom names.

These are candidate best-effort sources, not a promise that any live platform currently exposes every field. No signed-in live page was accessed in this task. If JSON is absent, malformed, over size/iteration limits or mismatched, only an independently identified DOM fallback may contribute. Facebook/Instagram email is intentionally not sought in unrelated page text. Never use a visited person's profile/feed item as the signed-in viewer. Avatar URLs are used only to find an image already loaded in the document; they are never assigned to a new image or fetched. Cross-origin pixels often cannot be read: initials are expected in that case. Browser fixtures also exercise downsampling already loaded 128×96 pixels to 64×48, tainted-canvas fallback and an unloaded URL producing no request.

Text limits: display name/handle 80 Unicode code points, email 254; control/bidi-format characters removed and whitespace normalized. Labels stay within the existing 40-character limit. Only PNG/JPEG/WebP data URLs with matching magic bytes, dimensions no greater than 64×64 and at most 32 KiB decoded are stored. Invalid or undecodable images use initials. Popup profile fields use text/value/src DOM properties and never enter HTML markup. Existing label usages elsewhere retain the escaped-label renderer.

Migration remains schema 1: optional profile data is sanitized on every load; missing metadata leaves legacy behavior. Session wipe removes cookie accounts, vault, all optional profiles and quarantine, preserves YouTube coordinates and custom labels, and resets automatic YouTube labels to “YouTube”. Full wipe removes the store. Neither wipe alters website cookies. See PRIVACY.md for storage/retention details.

Owner manual check: on each already logged-in platform, open the popup over that page, Add, inspect name/handle (and YouTube email if visible), rename, then Update session. Confirm the custom name survives, metadata belongs to the same viewer and avatar falls back gracefully when unreadable. Check an already open account menu only if desired; the extension must not open it. Do not enable TikTok until T2/T3 acceptance. Do not provide cookie values or account credentials in evidence.
